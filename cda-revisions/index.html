Fiches de révision : Titre CDA 2026

Supports de révision pour la soutenance du Titre Professionnel Concepteur Développeur d'Applications (RNCP 37873, niveau 6), spécialisation DevOps — alternance chez Sixense Engineering, EPSI Nantes.

Onze fiches réparties en deux familles. Les transverses couvrent la culture technique attendue en fin de cursus, illustrée systématiquement par du code des projets. Les projets décrivent chaque dépôt : architecture, choix, points sensibles. Chaque fiche suit le même plan : vocabulaire, TL;DR, détails techniques, code essentiel, questions probables du jury.

Un QCM de 70 questions complète le dispositif, avec correction et explication immédiates.

Fiches transversales

  • Transverse 1. Conception, UML et modélisation UML · Merise · MCD/MLD/MPD · ADR · PRD Les diagrammes produits (cas d'utilisation, classes, séquence, déploiement), les règles de passage MCD → MLD, les formes normales, l'architecture N-tiers, et la documentation versionnée dans le dépôt.
  • Transverse 2. Architecture et design patterns Strategy · Factory · SOLID · REST · monorepo Le refactoring du moteur de rendu (cascade de conditions → Strategy + Factory), l'architecture feature-based du front (ADR-005), monolithe contre microservices, et les patterns réellement présents dans le code.
  • Transverse 3. Sécurité, authentification et RGPD OIDC · OAuth2 · PKCE · JWT · OWASP · RGPD Le flow OIDC complet tel qu'implémenté, state / nonce / PKCE, le modèle BFF, le pont machine-to-machine borné par allowlist, l'OWASP Top 10 appliqué au projet, et les limites assumées.
  • Transverse 4. Tests, qualité et jeu d'essai pytest · Vitest · Playwright · Ruff · ESLint 1 591 tests sur trois niveaux, PostgreSQL réel en CI plutôt que SQLite, les factories, le jeu d'essai attendu par le référentiel, et ce que je testerais différemment.

  • Transverse 6. Bases de données, SQL et ORM PostgreSQL · ORM Django · migrations · JSONB Le modèle de données, les stratégies ON DELETE, la dénormalisation assumée du contenu en JSON, le queryset paresseux, le N+1, les pièges des migrations en production et le SQL à savoir lire.

Conseils de lecture

  • Première lecture : la section Vocabulaire et la TL;DR de chaque fiche, pour poser la carte mentale complète.
  • Seconde lecture : les détails techniques et le code essentiel, fiche par fiche.
  • Entraînement : le QCM, en mode aléatoire, jusqu'à ne plus se tromper sur les catégories faibles.
  • Veille de soutenance : uniquement les sections Questions probables du jury, et les encadrés Piège.

Ce que les encadrés signifient

Jury

Un angle d'attaque probable, ou la formulation à retenir pour répondre.

Piège

Une confusion courante, ou une question tendue attendant une réponse nuancée.

Attention

Une limite réelle du projet, à énoncer soi-même avant que le jury ne la trouve.

Note

Une précision technique utile mais secondaire.
